# Корень в реализации для сверки и пробах (URI.txt, редакция 2)

## Что и почему

Редакция 2 docs/URI.txt ввела корень, то есть URI центрального каталога:
`zip-document://v1/⟦U+002F⟧?archive=<P>` (URI 3.2–3.5, пример в 3.7, обоснование Р13). Всё в
`probes/uri-format` написано по редакции 1 и корня не знает:

- `uri.js` считает URI корня неканоническим, и `parse` возвращает на него `null`;
- `check.js`, `vscode-probe.js`, `ui-probe.js` и слепые прогоны (`blind/`) корень не покрывают.

Пока это так, гарантии раздела 4 (Т1, Т2, Т3, Т8) для корня держатся только на тексте, без
проверки. Это записано в URI 6.6 и 7. Кроме того, docs/PROVIDER.txt (редакция 2) опирается на
корень (разделы 2 и 3.10), а разбор URI провайдер берёт из `uri.js` (PROVIDER 7).

Уже существующие тесты корень не ломает. Отказ `'no entry'` в `check.js` и `'param entry dropped'`
в `blind/run.js` убирают entry, но оставляют path записи. По редакции 2 такой URI по-прежнему
неканоничен, и ожидаемый `null` остаётся верным.

## Что сделать

1. `uri.js`
   - Построение корня из архива с теми же условиями на P, что у `build`: если URI нет, отказ
     (3.3).
   - В `parse` третья ветвь: query из одной части `archive=<P>`; каноничен, если покомпонентно
     равен построенному URI корня.
   - Решить, в какой форме `parse` возвращает корень (например, `{ archive, root: true }` рядом с
     `{ archive, bytes, index }`). Это интерфейс для провайдера и редактора архива, его стоит
     выбрать сознательно.
2. `check.js`
   - Свойства на случайных архивах, включая вложенные: `parse(toString(u)) = u`, `toString()` —
     неподвижная точка, разбор возвращает тот же архив.
   - Метка корня не совпадает с меткой ни одной записи. Проверить на случайных именах и точечно
     на трудных: `/` (метка `/⟦⟧⟦U+002F⟧`), пустое имя, `a/`, текст `⟦U+002F⟧` в имени.
   - Отказы: path `/`, `/⟦⟧⟦U+002F⟧`, метка записи без entry; `archive=<P>&index=1`; метка корня с
     entry; неканонический P; архив с необычным портом (построение корня отказывает).
   - Точечно: строка из примера 3.7 совпадает символ в символ.
3. `vscode-probe.js`: URI корня через `workspace.fs`, `openTextDocument`, `vscode.open`, как `Uri` и
   как `Uri.parse(toString())`. Ожидаем, что URI доходит до провайдера без изменений и открывается
   одна вкладка. Итог записать в URI 6.3.
4. `ui-probe.js`: заголовок вкладки, описание, крошки и подсказка корня (ожидается `⟦U+002F⟧`).
   Открыть его вместе с записью `/` и записью-каталогом `a/` и проверить, что вкладки различимы.
   Итог записать в URI 6.4; Linux, затем Windows и macOS через `.github/workflows/uri-probes.yml`.
5. `blind/`
   - Добавить корень в интерфейс `task.md`.
   - Добавить случаи корня и его порчи в `run.js` и `bench.js`.
   - Пересобрать `PROMPT.md` через `make-prompt.js`.
   - Повторить прогон хотя бы на тех же четырёх моделях: подтвердить, что разделы 1–3 однозначны
     и для корня. НЕОДНОЗНАЧНОСТИ разбирать как раньше. Итог записать в README и URI 6.2.
6. Когда 1–5 сделано:
   - убрать пункт «Корень» из URI 6.6;
   - убрать фразу «Она написана по редакции 1» из шапки URI.txt и пункт про корень из URI 7;
   - убрать оговорку «корня в нём пока нет» из PROVIDER 7;
   - удалить этот тикет.

Порядок: сначала 1, затем 2, потом 3, 4 и 5 независимо друг от друга.

## Готово, когда

`uri.js` строит и разбирает корень. `check.js` проходит с новыми свойствами. Пробы VS Code
показали, что URI корня доходит без изменений и его вкладка различима, на трёх платформах.
Слепой прогон дал 0 расхождений с `uri.js`, включая корень. В URI.txt больше нет оговорок про
редакцию 1.
